# Security reporting

Do not include credentials, private datasets, runtime volumes or full request bodies in an issue. Once hosted on GitHub, use the repository's private vulnerability reporting feature if enabled. Until a private channel is configured, ask the maintainer for a private reporting channel without disclosing exploit details publicly.

Supported scope: the latest repository revision. This is a local reference application and should remain bound to loopback until independent identity, TLS, quotas and storage protection are deployed. The threat model is in `docs/security.md`.

A useful report includes affected revision, minimal synthetic reproduction, impact, environment, and a proposed mitigation if available. Do not test against anyone else's deployment without authorization.
